# Taste Yourself

> 一个连续的线上试衣空间：把衣服带到镜前，看静态效果、比较尺码差异，需要时再动起来 15 秒。

本项目正在建设微信小程序 MVP 与开源后端。产品只提供视觉体验和客观分析，不给尺码打分，不替用户作购买决定。

## 产品结构

首页不是功能卡集合，而是一面“试衣镜”：

```text
试衣镜首页
├── 最近一次试穿
└── 进入镜前
    ├── 静态试穿（默认）
    ├── 衣服轨道
    ├── 尺码差异抽屉
    └── 动一下 · 15s（可选实时模式）
```

当用户打开尺码差异但还没有尺寸画像时，才说明用途并提供相机扫描。扫描采用语音、屏幕轮廓与自动取帧引导，后台完成测量；用户可以跳过并继续使用试穿功能。成功提取尺寸后立即删除原始扫描帧。

完整定义见 [产品与系统总纲](docs/product-architecture.md)，尺码部分见 [尺码差异分析技术路线](docs/fit-analysis.md)。

从开发者工具到体验版的阶段、验收标准和外部依赖见 [交付计划](docs/delivery-plan.md)。

## API

### `POST /api/v1/fit/analyze`

输入：

- 用户胸、腰、臀等尺寸及穿着感受参照
- 商品品类、弹性
- 每个 SKU 的真实成衣尺寸

输出按请求中的尺码顺序返回，每个尺码包含：

- `assessment`：`below_reference`、`within_reference`、`above_reference` 或 `insufficient_data`
- 人体尺寸、成衣尺寸、穿着余量和参考区间
- 缺失的商品或人体测量项
- 中立文字说明

该接口不会返回 `recommended_size`、`score` 或 `confidence`。

### `POST /api/v1/fit-feedback`

记录用户实际穿着后的保留、换码、退货及部位感受，用于验证参考区间和监测长期误差。反馈不用于向当前用户强推购买结论。

## 技术路线

### 静态试穿

静态试穿是默认模式。衣服图片先完成主体提取、背景清理、品类识别与质量检查，再提交给可替换的虚拟试穿 Provider。它成本较低、容易比较，也是实时服务失败时的稳定回落状态。

### 实时试穿

实时能力通过 Provider 抽象接入 WebRTC/API。小程序原生环境需要验证 `live-pusher` / `live-player` 类目权限，并可能通过流媒体中转服务连接模型供应商。

单次会话最长 15 秒：用户主动点击“动一下”才建立连接，倒计时结束后释放昂贵资源并保留最后静态帧。实时能力失败不会阻塞衣橱、静态试穿或尺码分析。

### 尺码差异分析

基础公式：

`穿着余量 = 成衣围度 - 人体围度`

服务根据品类、弹性与用户选择的穿着感受参照，展示每个尺码的余量位于参考区间的什么位置。参考区间不是购买标准，用户可以结合视觉效果、面料偏好与使用场景自行判断。

### 相机身体测量

用户不需要先填问卷。需要尺寸数据时，由语音与画面逐步引导正面、侧面和缓慢转身，手机端进行完整入镜、清晰度、遮挡和姿态检查，后台完成尺度校准与参数化人体拟合。

自动测量必须携带来源、误差范围、模型版本和有效期。3DGS 或手机多视角重建可以辅助采集和展示，但在完成尺度标定及软尺真值验证前，不能直接当作厘米级测量结果。

## 系统边界

```text
衣服图 ─→ 清洗与标准化 ─→ 静态试穿 ─┐
                                      │
用户尺寸画像 ─┐                       │
               ├→ 尺码差异分析 ──────┼→ 镜前体验会话
SKU 成衣尺寸 ─┘                       │
                                      │
相机流 ─→ 实时 Provider（15 秒）──────┘
```

异步能力最终通过 `experience_session_id` 关联。详细接口与失败降级规则见 [产品与系统总纲](docs/product-architecture.md)。

## 数据与隐私

- 人体图像和尺寸属于敏感数据，扫描前需单独说明用途并取得同意。
- 权限按需申请；用户拒绝扫描时，非测量功能继续可用。
- 原始关键帧采取最小化采集、限时保存与可删除策略。
- 生成图片和视频需遵守适用的 AI 内容标识及平台审核要求。
- API 密钥只保存在服务端，客户端仅获得短期会话凭证。

## 开发顺序

1. 镜前页面：选衣、静态试穿、最近体验恢复。
2. 接入真实 SKU 成衣尺寸并完成尺码分析抽屉。
3. 在缺少画像时触发语音引导扫描，支持跳过与局部补拍。
4. 接入最多 15 秒的实时试穿并验证小程序链路。
5. 基于真实穿着反馈验证测量误差和参考区间。
6. 最后评估 3DGS、风格灵感与商业化扩展。
