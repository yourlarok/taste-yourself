# 实现状态看板

更新日期：2026-09-30

## 状态规则

本项目不使用主观完成百分比。每项能力只使用以下状态：

- **部分可用**：有真实子链路，但完成一次用户任务仍依赖人工步骤。
- **已配置待验收**：真实 Provider 已配置，但尚未通过健康检查、真机样本和失败恢复验收。
- **真实可用**：真实数据、真实服务、真机任务及失败恢复均已验收。
- **尚未配置**：代码合同存在，当前环境没有可调用的 Provider。

后端 `GET /api/v1/capabilities` 是运行环境状态的来源，小程序“我的”页直接展示该结果。配置 Provider 不等于服务健康，因此不会自动标为“真实可用”。

## 实施顺序

1. **基础环境门**：连接 HTTPS 后端，完成登录、上传、媒体读取和删除真机闭环。前端占位数据层已删除。
2. **静态试穿门**：先让最核心的试穿照跑真实模型，并建立样本验收记录。
3. **尺码数据门**：衣橱商品已支持在小程序录入 SKU 尺码表；继续接入人体测量真值。缺任一侧数据时只解释缺口，不猜尺码。
4. **实时试衣门**：接通 Decart WebRTC 并完成两端真机验收；连接失败明确不可用，不能回落到录制生成、静态帧或模拟结果。
5. **小范围内测门**：完成隐私、AI 标识、监控、成本上限和回滚开关后，再开放 10–30 人体验版。

## 任务进度呈现

用户任务不显示无法证实的百分比。静态试穿只显示“定格画面 → 上传素材 → 生成试穿照”三个由真实事件推进的阶段；上传衣服继续使用可由客户端获得的字节进度。工程交付则使用上面的验收门，不以“代码文件已存在”代替能力完成。

## 当前外部输入

- 正式 AppID/AppSecret、备案 HTTPS 域名和服务器。
- 百炼业务空间 Base URL、API Key，以及文本、视觉与 ASR 模型名。
- 淘宝开放平台 App Key/App Secret 与商品详情接口权限。
- 静态试穿当前使用已验证的 FASHN 托管 API；后续降本才需要 Ampere 及以上 GPU。
- 经标定的人体测量 Provider；必须能返回逐项误差和模型版本。
- 微信小程序已备案的 HTTPS `web-view` 业务域名，以及 iOS/Android 真机；Decart Lucy VTON 临时令牌签发已验证。
- 真实商品的逐 SKU 成衣尺寸数据；只有商品标题或用户通常穿着尺码不够。
