# 从原型到小范围内测的交付计划

本文件描述阶段与验收门槛；逐项实时状态及阻塞条件见 [实现状态看板](implementation-status.md)。

## 完成定义

“可发布小程序”不是页面能够编译，而是同时满足：核心流程可用、真实 Provider 接通、失败可恢复、敏感数据合规、后端可部署、真机验证通过、体验版账号能够完成任务。

## 阶段 1：开发者工具闭环

状态：代码闭环与微信开发者工具 CLI 编译/预览已通过，等待模拟器逐状态与真机人工验收。

- [x] 原生微信小程序工程可导入
- [x] 镜前单页及非卡片式功能整合
- [x] FastAPI、SQLite 与可恢复体验会话
- [x] 19 件原创服装目录及性别/体型/场景元数据
- [x] 后端尺码差异响应接入小程序
- [x] 未配置能力失败关闭，不返回固定画像或预置试穿结果
- [x] 内嵌实时镜页、Decart 短时客户端令牌和 WebRTC 前端连接代码
- [x] Provider 不可用时保留静态试穿与尺码分析能力
- [x] 自动化接口测试和代码静态检查
- [x] 微信开发者工具 CLI 编译并生成预览包
- [x] 魔镜 Agent、Qwen ASR、趣味镜卡、WHO-5 状态整理与猫猫图鉴
- [x] 淘宝开放平台导入、图片私有化和重复导入幂等
- [ ] 在模拟器与真机人工执行逐状态验收脚本

## 阶段 2：真实静态试穿与用户衣服

验收目标：真机上传一张衣服图，服务端完成合规检查和清洗，生成一张明确标识为 AI 的静态试穿图。

- [x] 微信登录与服务端会话
- [x] 本地私有媒体卷、签名 URL、上传限制和元数据清除（小规模单机方案）
- [x] 图片类型、尺寸和内容安全门控
- [x] FASHN VTON 1.5 Worker、HTTP 适配器与超时
- [x] 用户衣服上传、衣橱读取与最近体验恢复
- [x] 上传内容及生成内容安全 Provider
- [ ] 在 Ampere 及以上 GPU 上下载权重并完成真实生成验收
- [ ] 扩容前迁移对象存储、任务队列和幂等作业

## 阶段 3：真实尺寸画像

验收目标：在受控测试人群中，与软尺真值比较并记录误差；误差超出阈值时不输出厘米值。

- [x] 相机语音、轮廓、震动和自动取帧状态机
- [x] 正面/侧面方向、分辨率、内容安全门控与补拍响应合同
- [x] 后台人体测量 HTTP Provider
- [x] 每项尺寸来源、误差范围与用户画像持久化
- [x] 原始扫描帧成功处理后立即删除，支持画像/全账号删除
- [ ] 接入经标定的真实测量服务，并记录模型版本与有效期
- [ ] 建立软尺标定集与 MAE/P95/重复性报告

## 阶段 4：Decart 实时动态试穿

验收目标：在小程序同源内嵌镜页中，微信真机将相机流持续发送至 Decart，并显示模型返回的实时换装流。任何失败都显示不可用，不允许回落到录像生成、静态帧或 mock。

- [x] Decart SDK WebRTC 和同源 WebView 页面打包
- [x] 后端签发限定模型、来源和会话时长的临时客户端令牌
- [x] 退出/页面切后台时关闭实时客户端与本地相机轨道
- [ ] 配置 Decart 实时 Lucy VTON Key 并部署构建产物
- [ ] 在微信 iOS 与 Android 真机测试授权、回传、换衣、弱网、来电、切后台与断流

## 阶段 5：体验版内测

验收目标：10–30 名体验成员完成规定任务，问题可追踪，敏感数据和成本可控制。

- 正式 AppID、HTTPS 域名与后台域名白名单
- 隐私保护指引、AI 内容标识、服务类目与审核材料
- 生产数据库、对象存储、日志、告警、备份和删除任务
- 错误追踪、Provider 成本、实时会话成功率与断流指标
- 内测任务卡、反馈入口、版本回滚和停止开关
- 上传开发版、设为体验版、添加体验成员并收集反馈

## 需要用户提供的外部资源

进入真实体验版前仍需提供：正式 AppID/AppSecret、已备案 HTTPS 域名/服务器、百炼文本/视觉/ASR、淘宝开放平台、静态试穿服务、经标定的测量服务、Decart 实时试衣权限，以及微信小程序 WebView 业务域名配置。

所有密钥仅写入服务端环境变量，不提交 Git，也不进入小程序代码包。
