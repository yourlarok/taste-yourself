# 产品与系统总纲：连续的线上试衣空间

## 1. 产品定位

Taste Yourself 不是导购裁判，也不是三个工具的集合。它是用户网购时可以随时进入的线上试衣空间：把衣服带到“镜前”，观察穿着效果、比较不同尺码的客观差异，再由用户自己决定。

产品遵守三条边界：

1. 分析，不打分；展示差异，不给单一答案。
2. 试穿图是视觉模拟，不证明真实合身或面料物理效果。
3. 购买决定始终留给用户，不用“最适合”“建议购买”等措辞制造确定性。

## 2. 体验核心与能力层级

| 层级 | 能力 | 首版角色 | 说明 |
|---|---|---:|---|
| 产品核心 | 镜前体验会话 | 必须 | 串起衣服、静态画面、尺码差异与可选动态模式 |
| 默认体验 | 静态试穿 | 必须 | 进入后即可获得低成本、可停留比较的视觉结果 |
| 领域基础 | SKU 成衣尺寸标准化 | 必须 | 尺码分析的数据基础；缺失时明确展示数据不足 |
| 领域基础 | 用户尺寸画像 | 必须 | 可来自相机扫描、历史记录或用户主动修正，并记录来源与误差 |
| 分析能力 | 中立尺码分析 | 必须 | 按原顺序展示各尺码余量与参考区间，不排序、不评分、不推荐 |
| 数据入口 | 语音引导身体扫描 | 条件触发 | 用户需要尺码分析且没有可用画像时出现，不阻塞普通试穿 |
| 增强体验 | 15 秒实时试穿 | 可选 | 用户主动点击“动一下”后临时进入，结束后回到静态画面 |
| 技术增强 | 多视角/3DGS | 可选 | 辅助采集或展示；未经标定不能当作厘米级测量真值 |
| 探索能力 | 风格灵感与搭配尝试 | 后续 | 提供更多可试内容，不根据行为替用户下审美结论 |

## 3. 界面整合原则

首页不使用“尺码分析 / 静态试穿 / 实时试穿”三张并列功能卡。它们不是三个目的地，而是同一次试衣体验中的不同层次。

```text
首页：试衣镜（主视觉就是镜面/取景空间）
├── 最近一次试穿：轻量入口，可继续上次体验
└── 进入镜前
    ├── 默认：静态试穿画面
    ├── 衣服轨道：切换或添加衣服
    ├── 查看尺码差异：从底部展开分析抽屉
    └── 动一下 · 15s：临时进入实时模式
```

“相机”是实现媒介，不是产品名称。推荐界面语言使用“试衣镜”“镜前”“试衣空间”“动一下”，减少工具感和技术感。

最近体验也不叫“报告中心”。首页只展示一条安静的“上次试穿”；进入后再查看当时的画面和尺码差异。只有当需要导出或长期回顾时，才使用“试穿记录”。

## 4. 用户流程

```text
打开小程序
  ↓
看到试衣镜与上次试穿
  ↓
进入镜前并选择衣服
  ↓
立即生成/恢复静态试穿
  ├── 切换衣服 → 更新静态画面
  ├── 查看尺码差异
  │     ├── 有尺寸画像 → 展开各尺码客观差异
  │     └── 无可用画像 → 解释用途 → 用户选择是否扫描
  │                              ├── 同意 → 语音与轮廓引导采集
  │                              └── 跳过 → 保留试穿，不显示伪精确分析
  └── 动一下 → 开启 15 秒实时试穿 → 自动回到最后静态帧
```

扫描引导一次只给一个动作，质量合格后后台自动取帧处理；失败时只补拍对应角度。权限在真正开始扫描或实时试穿时申请，不在首页提前索取。

## 5. 信息呈现

尺码抽屉按商品原始尺码顺序展示，例如：

| 尺码 | 已知事实 | 中立描述 |
|---|---|---|
| M | 胸部余量 2 cm | 低于当前参考区间，可能呈现更贴身的效果 |
| L | 胸部余量 8 cm | 位于当前参考区间 |
| XL | 胸部余量 16 cm | 高于当前参考区间，可能呈现更宽松的效果 |

禁止展示综合分、冠军尺码、购买按钮旁的强推标签，以及把统计相关性写成确定事实。参考区间、人体测量和成衣测量都应允许查看来源；数据不足就明确说明缺哪一项。

## 6. 模块关系

```text
衣服图 ─→ 清洗/标准化 ─→ 静态试穿 Provider ─┐
                                              │
相机/历史记录 ─→ 用户尺寸画像 ─┐             │
                                ├→ 中立尺码分析 ├→ 镜前体验会话
SKU 成衣实测尺寸 ──────────────┘             │
                                              │
相机流 ─→ 可替换实时 Provider（15 秒）────────┘
```

视觉模型不能写入尺码结论。尺码分析只消费人体尺寸与真实成衣尺寸；静态和实时 Provider 均可替换，任何单一供应商失败都不应破坏整个体验。

## 7. 会话与接口

所有能力通过 `experience_session_id` 关联同一次镜前体验：

```text
experience_session_id
├── user_id
├── product_id / garment_id
├── fit_profile_version       # 可空
├── catalog_fit_version       # 可空
├── body_scan_job_id          # 可空
├── static_tryon_job_id       # 可空
├── realtime_session_id       # 可空
└── fit_analysis_id           # 可空
```

建议接口：

- `POST /api/v1/experience-sessions`：进入镜前或恢复最近体验
- `POST /api/v1/body-scans`：在需要尺寸画像时创建采集任务
- `POST /api/v1/body-scans/{id}/complete`：完成关键帧上传并异步处理
- `GET /api/v1/body-scans/{id}`：查询质量、处理阶段和补拍要求
- `POST /api/v1/fit/analyze`：现有中立尺码分析接口
- `POST /api/v1/tryon/static`：生成或更新静态试穿
- `POST /api/v1/tryon/realtime-sessions`：创建最长 15 秒的实时会话
- `POST /api/v1/fit-feedback`：记录实际穿着反馈，用于验证参考区间

异步任务状态统一为：

`created → uploading → validating → processing → needs_retake | completed | failed`

## 8. 失败与降级

| 失败点 | 产品行为 |
|---|---|
| 扫描质量不足 | 说明具体角度或遮挡问题，只补拍失败部分 |
| 无可靠绝对尺度 | 不生成厘米级人体尺寸，仍允许普通试穿 |
| SKU 缺少成衣尺寸 | 展示视觉试穿，并说明暂时无法比较尺码差异 |
| 静态模型失败 | 保留原图、衣橱和尺码分析入口，允许重试 |
| 实时模型或网络失败 | 自动回到静态画面，不丢失当前衣服与上下文 |
| 用户拒绝敏感信息处理 | 不启动身体扫描，其他非测量功能继续可用 |

## 9. 首版验收顺序

1. 一个镜前页面能完成选衣、静态试穿和最近体验恢复。
2. 真实 SKU 成衣尺寸可导入、校验并追踪数据版本。
3. 尺码抽屉按原始顺序解释每个尺码，不出现评分或推荐字段。
4. 缺少用户画像时，语音引导扫描可被触发、跳过和局部重拍。
5. 实时试穿严格限制为 15 秒，并能无损回落到静态画面。
6. 真实穿着反馈能关联到画像、商品数据与分析版本。
7. 最后再评估 3DGS、风格灵感和商业化扩展。
