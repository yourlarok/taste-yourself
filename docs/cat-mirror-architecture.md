# 猫猫魔镜架构

## 产品核心

首页只有一个主要对象：魔镜。用户通过自然语言表达目的，Agent 识别意图后调用受控工具，
而不是让用户先理解一组功能入口。试衣间、衣橱、趣味镜卡、状态整理和图鉴都保留独立页面，
但它们是 Agent 的执行空间。

## 真实能力边界

- 镜子对话：服务端 OpenAI 兼容接口，生产环境必须配置百炼等真实模型，不提供模拟回复。
- 趣味镜卡：视觉模型只提取可直接观察的画面特征，再与三项用户自述做分层校准；每天一次。
  禁止从脸推断人格、命运、健康、族群、年龄或性别。
- 状态整理：基于 WHO-5 结构的五题自评，分数是过去两周心理幸福感的自我观察，不是诊断；
  安全风险优先给出现实支持路径。
- 试衣：静态使用 FASHN，实时使用 Decart WebRTC；Agent 可向实时页面传递受控场景词。
- 尺码：真实人体测量与逐 SKU 成衣尺寸表相减，只展示差异，不推荐购买决定。
- 淘宝链接：必须通过获授权的官方商品接口导入，不以抓网页代替正式链路。

## Agent 工具

`open_tryon`、`show_garments`、`open_wardrobe`、`start_fun_face`、`start_wellbeing`、
`open_atlas`。所有模型输出都经过 Pydantic 校验、意图白名单和衣服 ID 白名单；场景只允许
`beach`、`city`、`cafe`、`garden`、`studio`、`snow`、`sunset`。

## 数据与隐私

对话和卡片归属微信用户。趣味镜卡原图在视觉分析后立即删除；身体扫描帧在测量结束后删除；
删除画像时同步请求删除外部测量记录。大模型密钥、微信密钥和供应商密钥只存在服务器环境变量。
