# 微信小程序前端重构 Agent 提示词

下面整段内容可直接交给负责前端的 Agent。不要把它当作概念稿；必须在微信开发者工具中实现、编译、逐状态截图并验收。

---

你是一名资深微信小程序产品设计师和原生小程序前端工程师。请重构 Taste Yourself（线上试衣空间）的完整小程序前端。

## 一、你的工作边界

- 只修改 `miniprogram/`、必要的 `project.config.json` 前端工程配置，以及前端测试/检查脚本。
- 不修改 `server/`、`workers/`、后端数据模型或 API 语义。
- 必须使用原生微信小程序 WXML、WXSS、JavaScript；不要换成 H5、uni-app、Taro 或云开发。
- 必须真实导入微信开发者工具验证，不能只做静态 HTML 效果图。
- 开始前先阅读：
  - `README.md`
  - `docs/product-architecture.md`
  - `docs/fit-analysis.md`
  - `miniprogram/services/api.js`
  - `server/app/domain/experience.py`
  - `server/app/domain/models.py`
- 保持现有后端接口可用；如果认为接口不足，在单独的“后端需求”文档中提出，不要自行更改后端。

## 二、产品定位（不可改）

这不是导购工具、功能卡集合或尺码推荐器，而是用户网购时进入的“线上试衣空间”。

产品原则：

1. 分析，不打分。
2. 展示尺码差异，不推荐唯一尺码，不替用户做购买决定。
3. 静态试穿是默认核心；尺码分析是上下文能力；15 秒动态试衣是可选增强。
4. 相机是实现媒介，不是产品名称。界面语言使用“镜前”“试衣空间”“试穿照”“动一下”等自然表达。
5. 用户没有尺寸画像时，普通试穿仍然可用；只有主动查看尺码差异时才解释并邀请扫描。
6. 不使用“最适合”“推荐购买”“得分”“准确率百分比”等制造确定性的表达。

## 三、首先解决当前首页的根本问题

当前首页的大面积镜子只是装饰，不能点击、没有信息、进入后又是另一套界面，因此属于无效内容。新首页的每一块可见区域必须满足至少一个条件：

- 能直接操作；
- 展示与当前用户有关的信息；
- 明确解释下一步；
- 提供连续体验入口。

禁止再放一个占据大半屏、不能点击、没有状态和内容的装饰镜面。

## 四、首页：设计成“试衣准备空间”

首页不是营销落地页，也不是三个功能卡。推荐结构如下。

### 1. 顶部区域

- 遵守自定义导航栏安全区，绝不能与状态栏、刘海或微信右上角胶囊重叠。
- 左侧显示克制的产品名称/标识；右侧“我的”入口必须避开胶囊。
- 不放说明性长文，不放技术术语。

### 2. 主舞台（全区域可点击）

主舞台占首屏主要视觉面积，但必须是一个完整交互入口，点击任意位置都进入镜前。

有最近试穿时：

- 背景展示最近一次试穿结果图；若无结果图则展示当前衣服图与克制的取景占位。
- 显示衣服名称、更新时间，以及明确动作“继续上次试穿”。
- 提供轻量的“更换衣服”入口，但不要把操作拆成卡片矩阵。

没有最近试穿时：

- 展示真实可理解的首次使用状态，不使用抽象人体色块。
- 内容应包含：“选择或拍一件衣服 → 站到镜前 → 生成试穿照”的三步微文案，可沿镜面边缘纵向排布，不能做成三张大卡。
- 整个区域仍可点击进入；主动作写“开始第一次试穿”。
- 可以在主舞台内展示一件真实演示衣服缩略图，说明“可先用示例衣服体验”。

主舞台必须有按压反馈；点击后视觉上连续过渡到镜前页面，不能像跳进毫不相关的第二个产品。

### 3. 与用户有关的内容带

在主舞台下方放一条紧凑的上下文内容带，而不是堆卡片：

- 上次试穿：衣服名称、时间、缩略图；无记录时显示“还没有试穿记录”。
- 我的衣橱：展示最多 3 件真实缩略图和总数，末尾是“添加衣服”。
- 尺寸画像状态只用一行状态表达：
  - 已有画像：“尺寸画像已建立 · 可查看尺码差异”；
  - 没有画像：“需要比较尺码时再建立，不影响试穿”。
- 不要在首页主动弹扫描授权，不要把尺寸画像做成强制 onboarding。

如果屏幕空间不足，优先保留主舞台、最近试穿和主动作；衣橱预览可折叠为一行横向列表。

### 4. 首页唯一主动作

- 页面只有一个最高强调级按钮：“进入镜前”或“开始试穿”。
- 主舞台本身与按钮执行同一动作。
- “尺码分析”“静态试穿”“实时试穿”不能作为首页三个并列入口。

## 五、镜前页面：相机是核心画布

### 1. 画面层级

- 相机/结果图全屏铺底。
- 顶部只有返回、当前状态和保存；避开微信胶囊。
- 状态文案最多一行，例如“选择衣服后生成试穿照”“正在生成…”“结果已更新”。
- 网络/后端不可用是状态提示，不要长期占据大面积。

### 2. 衣服选择

- 示例衣服和用户衣橱都必须显示真实缩略图与名称。
- 严禁用三个无标签色块代表衣服。
- 当前选择必须清晰，但不要使用粗重发光边框。
- 横向衣服轨道末尾提供“添加衣服”；上传中、审核失败、图片失败都要有独立状态。
- 添加衣服调用现有 `wx.chooseMedia` 和上传接口；上传前应说明衣服图要求。

### 3. 静态试穿主动作

- “生成试穿照”是镜前页面唯一主操作。
- 使用清晰的快门/生成语义，并显示当前选中的衣服名称。
- 生成中防止重复提交，展示可感知进度状态；失败后保留相机、衣服和重试入口。
- 结果图必须带“AI 生成效果，仅供视觉体验”提示。
- 点击结果图回到相机时需要明确提示，不允许用户误以为结果丢失。

### 4. 二级能力

在主动作下或同一底部操作层中放两个二级入口：

- “尺码差异”：打开底部抽屉，不跳转成独立工具首页。
- “动态试衣 · 15 秒”：用户主动触发，显示倒计时，结束或失败后回到静态上下文。

二级入口视觉权重必须低于“生成试穿照”。

## 六、尺码差异抽屉

- 结果只分析，不打分、不排序、不推荐。
- 按商品原始尺码顺序展示，例如 M、L、XL。
- 每个尺码展示：人体尺寸、成衣尺寸、余量、相对参考区间的位置、中立说明。
- 明确展示数据来源和测量误差；允许展开查看。
- 缺少商品尺码数据时，说明“仍可继续视觉试穿”。
- 缺少用户尺寸画像时，先解释用途、采集内容、删除策略，再由用户选择“建立尺寸画像”或“暂不建立”。
- 不允许用绿色/红色表达“正确/错误尺码”；颜色只用于信息层级。

## 七、尺寸画像采集

- 由用户从尺码抽屉主动进入，不能首页强制。
- 一次只显示一个动作，使用轮廓、中文语音、震动和倒计时引导。
- 正面、侧面分别显示采集状态；不合格时只要求补拍具体角度。
- 处理阶段区分：上传、检查画面、计算尺寸、完成。
- 用户取消或拒绝授权后回到原试穿上下文，不能丢失衣服和结果。
- 明确说明成功提取后原始扫描帧会删除。

## 八、15 秒动态试衣

- 点击后二次确认这是 15 秒可选体验，并说明可能消耗更多流量。
- 建立链路时显示连接态，成功后才开始倒计时。
- 倒计时始终可见，用户可提前结束。
- 弱网、切后台、权限拒绝、Provider 不可用时自动回到最后静态画面。
- 失败不能清空当前衣服、静态结果或尺寸分析上下文。

## 九、“我的”与隐私

- 内容包括：今日静态/动态用量、尺寸画像状态、隐私保护指引、清除尺寸画像、删除全部数据。
- 删除全部数据必须二次确认并准确说明范围。
- 相机、相册、保存权限在真正执行动作时申请，不在启动页一次性索取。
- 修复当前无效的 `app.json permission` 配置警告；以当前微信基础库的真实权限机制为准。

## 十、完整状态设计

以下状态必须逐一实现，不能只做理想成功态：

- 首次用户 / 有最近记录；
- 登录初始化中 / 登录失败可重试；
- 后端在线 / 本地演示或后端不可用；
- 相机授权待申请 / 拒绝 / 系统不支持；
- 衣橱为空 / 上传中 / 上传失败 / 内容审核拒绝；
- 静态试穿待生成 / 生成中 / 成功 / 失败 / 达到每日限额；
- 尺寸画像缺失 / 处理中 / 需要补拍 / 已完成 / 已过期或不可用；
- 商品尺码数据缺失；
- 动态链路连接中 / 15 秒进行中 / 主动结束 / 弱网失败 / 达到限额；
- 数据删除中 / 成功 / 失败。

错误提示必须告诉用户“发生了什么、当前内容是否保留、下一步能做什么”，不要只写“失败”。

## 十一、视觉与版式要求

- 气质：安静、克制、可信、偏编辑设计，不做电商促销页，不做科技仪表盘。
- 色彩：暖中性色为主，一个低饱和强调色即可。禁止用随机渐变色块代替内容。
- 信息层级：一个主舞台、一个主动作、少量上下文；不要处处套卡片。
- 间距采用统一 8rpx 基线体系；建立明确的字号、圆角、阴影和颜色 token。
- 所有点击区域至少 88rpx；文本在小屏、刘海屏和大字号下不能截断。
- 不使用无意义英文装饰词；如果英文不帮助理解就删除。
- 动效只用于连续性和状态反馈：页面进入、抽屉、选衣切换、生成等待、结果出现。单次 180–280ms，尊重减少动态效果设置。
- 使用真实衣服图片、结果图和内容骨架屏；不要用纯色矩形冒充最终内容。

## 十二、现有 API 映射

所有请求均通过 `miniprogram/services/api.js`，使用登录后的 Bearer Token。

| 场景 | API |
|---|---|
| 微信登录 | `POST /api/v1/auth/wechat` |
| 开发者工具登录 | `POST /api/v1/auth/dev-login` |
| 示例衣服 | `GET /api/v1/catalog/garments` |
| 我的衣橱 | `GET /api/v1/wardrobe/garments` |
| 上传衣服 | `POST /api/v1/wardrobe/garments` |
| 最近试穿 | `GET /api/v1/me/recent-experience`，404 表示无记录 |
| 今日用量 | `GET /api/v1/me/usage` |
| 尺寸画像状态 | `GET /api/v1/me/fit-profile`，404 表示未建立 |
| 进入镜前 | `POST /api/v1/experience-sessions` |
| 切换衣服 | `PUT /api/v1/experience-sessions/{id}/garment` |
| 上传本人画面 | `POST /api/v1/person-images` |
| 静态试穿 | `POST /api/v1/experience-sessions/{id}/static-tryon` |
| 尺码差异 | `GET /api/v1/catalog/garments/{id}/fit-analysis` |
| 创建扫描 | `POST /api/v1/body-scans` |
| 上传扫描帧 | `POST /api/v1/body-scans/{id}/frames` |
| 完成扫描 | `POST /api/v1/body-scans/{id}/complete` |
| 动态试衣 | `POST /api/v1/experience-sessions/{id}/realtime` |
| 清除画像 | `DELETE /api/v1/me/fit-profile` |
| 删除全部数据 | `DELETE /api/v1/me/data` |

必须根据 HTTP 状态码处理：

- 401：重新登录后最多重放一次安全请求；
- 404：无最近记录、无画像或资源不存在，按具体接口显示空态；
- 409：需要尺寸画像；
- 422：图片/画面不合格或内容审核未通过；
- 429：达到当日额度；
- 503：Provider 或内容安全服务暂不可用，保留上下文并允许稍后重试。

## 十三、前端状态机

不要用大量互相独立的布尔值拼 UI。至少明确维护以下状态：

```text
home: loading | empty | ready | error
studio: preparing | camera | capturing | generating | result | degraded
fit: idle | profile_required | loading | ready | missing_product_data | error
scan: consent | front | side | uploading | processing | needs_retake | completed | failed
realtime: idle | connecting | active | ending | unavailable
```

页面切后台时终止扫描计时器和动态会话；返回后恢复静态上下文。

## 十四、代码质量要求

- 拆分为清晰组件，不要继续把所有结构、状态和方法堆在一个超大页面中。
- 推荐组件：`mirror-stage`、`garment-strip`、`tryon-controls`、`fit-sheet`、`scan-guide`、`account-sheet`、`state-feedback`。
- 建立 `styles/tokens.wxss` 或等价设计 token。
- WXML 不写复杂业务表达式；派生状态放到 JS 中。
- 定时器、音频、live context 在 `onHide/onUnload` 中完整释放。
- 保持媒体 URL 签名参数，不自行拼接或缓存过期地址。
- 不把 AppSecret、Provider Token 或后端密钥写入小程序。

## 十五、交付物与验收

必须交付：

1. 可直接导入微信开发者工具的完整前端代码；
2. 首页、镜前、尺码抽屉、扫描、动态、我的页面/抽屉；
3. 设计 token 与组件目录说明；
4. 所有状态的交互说明；
5. 微信开发者工具真实编译与预览结果；
6. 以下截图，使用同一 iPhone 模拟器尺寸：
   - 首次首页；
   - 有最近试穿的首页；
   - 镜前相机态；
   - 静态结果态；
   - 尺码分析完整态；
   - 缺画像解释态；
   - 扫描正面/侧面态；
   - 15 秒动态态；
   - 网络失败和额度耗尽态。

验收红线：

- 首页不存在占大面积却不能操作的空装饰；
- 不存在无标签衣服色块；
- 不与微信胶囊、刘海、底部安全区重叠；
- 不出现三张并列功能卡；
- 不出现推荐尺码、评分或替用户决策的文案；
- 主流程在后端失败时仍能恢复和继续；
- `preview` 成功不算完成，必须检查模拟器真实渲染截图；
- 所有改动通过仓库检查，并保持后端测试不受影响。

完成后先提交截图和状态清单供审阅，再提交 Git。
